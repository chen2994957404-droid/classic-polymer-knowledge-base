# 全书分阶段处理工作流

## 总目标

将扫描版高分子物理教材逐步整理为中文、非逐字、教材式知识库。项目不追求复制教材原文，而是通过小批次、人工复核和 ChatGPT 学术重构，形成可长期维护的学习笔记体系。

## 角色分工

- ChatGPT：负责学术重构、公式检查、概念解释、术语统一、最终质量复核。
- Codex：负责工程流程、文件组织、脚本、批次记录、模板和复核报告。
- 人工复核者：负责查看本地源图、确认页码边界、判断模糊内容和版权风险。

## 原始文件安全原则

- 原始 PDF 必须保留在 `01_raw_local/source_books/`。
- 页面图片必须保留在 `01_raw_local/page_images/` 或其他 `01_raw_local/` 子目录。
- 原始 OCR 必须保留在 `01_raw_local/raw_ocr/`。
- 不提交原始 PDF、页面图片、原始 OCR 或全文转录。
- 跟踪文件只保存流程、元数据、复核记录、非逐字学习笔记和 Notion-ready 摘要。

## 默认批次策略

- 默认 2-5 页一批。
- 优先一个小节一批。
- 公式推导密集处应缩小批次，并优先生成公式复核记录。
- OCR 工具不可用时，优先使用人工复核要点。

## Codex 停止点

Codex 应在以下情况停止并请求 ChatGPT 或人工复核：

- 小节草稿完成但公式、术语或图表需要学术判断。
- 页码边界或小节边界不清。
- 内容可能过于接近原文。
- OCR 噪声高或 OCR 工具缺失。
- 新命令会触及 `01_raw_local/` 或超过批准批次。

## 人工介入点

- OCR 工具安装或配置。
- 扫描页旋转、裁切、模糊、页序异常。
- 年份、人名、参考文献、公式符号无法从结构化内容确认。
- 版权风险不明确。

## 每批次固定检查

```text
git status --short
git diff --check
```

每批次必须记录：是否运行 OCR、是否触碰 raw 文件、是否有提交或推送。默认答案应为“否”。
